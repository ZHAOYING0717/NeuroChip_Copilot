# NeuroChip Copilot 使用说明

## 启动

```powershell
.\.venv\Scripts\Activate.ps1
streamlit run app.py
```

浏览器打开 `http://localhost:8501`。仓库自带轻量示例和模型，不下载完整数据也能运行。

## 单条记录

1. 在侧栏选择“单记录”。
2. 选择“公共数据集（仅供示例）”时，先选数据集，再选具体记录；也可以上传 MAT、HDF5、CSV。
3. 若文件没有可靠时长，可勾选“指定记录时长”。
4. 依次查看“质量控制”“放电活动”“网络与临界性”“模型解释”。
5. 先确认通道状态和六段记录稳定性，再解释功能状态轴分位与参考偏离分位。
6. 在总览底部下载 PDF 或 HTML 报告。

完整本地数据目前提供四组公开样本：45 条前脑类器官参考记录、19 条脑类器官地西泮记录、198 条 GIN 二维神经元孔-阶段记录，以及 72 条 Trujillo 皮层类器官孔-阶段记录。轻量提交包为每个来源保留至少一条可运行记录，并包含一组地西泮类器官和一组 Trujillo 类器官匹配配对。轻量网页用“演示数/完整数”同时标出实际随包记录数和完整公开数据规模，避免把演示子集误认为训练或验证样本量。GIN 二维神经元与其他实验平台记录的参考分位仅作跨数据域探索，不应解释为类器官健康或疾病判断。

推荐使用 NeuroChip 1.0 标准列：

```text
recording_id,timestamp_s,channel_id,amplitude_uv,duration_s,well_id,source_vendor,schema_version
```

上传面板提供“下载标准 CSV 模板”。上传后系统会先检查文件是否可读取、时间和通道列是否存在、时间是否为秒且非负、事件是否为空，以及记录时长是否为正数。没有 `duration_s` 时会根据最大事件时间推断，并给出提示；一个文件含有多个 `well_id` 时会提示先按孔位拆分。

网页上传的是检测后的 spike 事件表，不是连续原始电压波形。原始电压不能直接按当前事件分析流程使用；噪声、漂移、饱和和电极阻抗仍需使用原始波形及采样频率进行单独 QC。

旧格式 `channel,time_s` 仍可读取。Axion 导出的 `Channel,Time` 可用以下命令分块转换，断线或中断后可续跑：

```powershell
python scripts/convert_to_neurochip.py input.csv output.csv --well A1 --resume
```

## 多维干预功能评价

1. 选择“干预评价”。
2. 可以直接选择“公共数据集（仅供示例）”；也可以选择“上传数据”，一次上传至少两份同一实验对象或匹配实验单元的记录。每份文件都会先做格式预检。
3. 从文件列表中指定“基线记录”和“处理后记录”。基线可以是处理前、零剂量或匹配载体对照，但必须在实验设计中有明确含义。
4. 选择本次处理的预期目标：仅量化影响、降低过度活动、增强低活动网络、降低过度同步、保持功能稳定，或向参考状态靠近。
5. 如有匹配健康对照，可将第三份记录选为参考；否则系统使用公开训练队列的稳健中心，该中心不是临床健康标准。
6. 如有洗脱后或恢复期记录，可将另一份记录选为恢复记录，用于评价变化是否回到基线。
7. 输入各记录共同的协议时长，先检查基线和处理后的事件质量，再查看结论。

页面把结果分为六部分：

- **多维影响幅度：** 18 个已验证功能指标合在一起变化了多少，不判断方向好坏。
- **目标一致性：** 变化方向是否符合用户预先选择的实验目标。没有目标时显示“不适用”。
- **参考距离：** 处理后是更接近还是更远离指定参考；它不是疾病概率或健康分数。
- **网络沉默风险：** 放电率与活跃通道是否同时大幅下降。高风险会覆盖表面上的“抑制符合目标”。
- **恢复程度：** 有恢复期记录时，量化处理效应回到基线的比例。
- **证据等级：** 结合事件质量和多指标一致性给出解释强度。单个前后配对最高只标为中等证据。

“高级探索”中的稳定性、神经雪崩和信息流用于机制观察，当前不参与处理好坏总评。“辅助响应分数”只回答两个 spike timing 指标改变得多不多；它不单独判断疗效、毒性或好坏。地西泮剂量映射只在明确的公开地西泮配对中显示，其他化合物、外部数据和普通上传记录均标为不适用；该映射只用于方法展示，不用于实际给药或药效结论。

没有合理基线时，不应使用本模式解释处理效应。正式实验结论还需要载体或时间对照、生物学重复和组间统计，单个前后配对不能替代这些设计。

## 项目管理

1. 选择“项目”，新建一个实验项目。
2. 为样本填写名称、分组、处理和备注。
3. 可以登记样本，也可以直接分析公开样本并把结果写入项目。
4. 项目、样本和分析摘要保存在本地 SQLite 数据库 `artifacts/projects/neurochip_projects.sqlite3`。

该功能适合本地科研整理，不是多人协作数据库，也不是经过验证的 LIMS。

## 质量控制怎么理解

- `good`：事件层面未发现明显问题。
- `inactive_candidate`：当前事件文件中活动不足，只能称为不活跃候选，不能直接说电极坏了。
- `review_event_proxy`：重复、超短间隔或越界事件提示需要复查。
- `excluded_event_invalid`：事件时间无效，应排除。
- 稳定性把记录等分成六段，报告放电稳定性 CV、末段与首段活动比和变化趋势。

如果有连续原始电压，代码库中的 `assess_raw_voltage_quality(...)` 可以检查噪声、漂移、工频、饱和和近似死通道；网页上传的 spike event 本身不能完成这些判断。

## 结果解释顺序

1. 事件是否越界、重复或存在大量短间隔。
2. 活跃通道比例和单通道支配是否合理。
3. 放电、ISI、STTC、网络、爆发和神经雪崩特征是否共同支持解释。
4. 互信息、传递熵和预测性 Granger 只作为统计关联描述，不能当成已经证明的因果连接。
5. 参考偏离分位由哪些 Shapley 贡献驱动。
6. 干预评价是否有明确目标、合理基线、质量门控、匹配对照、生物学重复和足够样本。

## 禁止解释

- 不把事件质量分数称为原始电压质量。
- 不把参考偏离分位称为疾病概率或毒性概率。
- 不把功能状态轴分位称为健康、成熟度或临床评分。
- 不把探索性剂量估计用于给药决策。
- 不把传递熵或预测性 Granger 方向说成突触因果关系。
- 不省略数据来源、许可证、样本量和验证分组。
